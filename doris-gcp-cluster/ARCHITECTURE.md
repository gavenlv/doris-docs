## 核心组件说明

### 1. Frontend (FE) 集群

**作用**: 管理 metadata、处理 SQL 查询、协调 BE

**部署**:
- DEV: 1 个节点 (单点)
- SIT/UAT: 2 个节点 (HA)
- PROD: 3 个节点 (完全 HA)

**存储**:
- 独立持久化磁盘 (`pd-balanced` 或 `pd-ssd`)
- 存储 FE 元数据
- 销毁实例后磁盘保留

**端口**:
- 9030: MySQL Protocol (查询)
- 9020: RPC
- 9010: Edit Log
- 8030: HTTP Web UI

### 2. Backend (BE) 集群

**作用**: 存储数据、执行查询、处理数据读写

**部署**:
- DEV: 2-5 个节点 (自动扩缩容)
- SIT: 3-8 个节点 (自动扩缩容)
- UAT: 4-10 个节点 (自动扩缩容)
- PROD: 5-20 个节点 (自动扩缩容)

**存储**:
- 独立持久化磁盘 (`pd-ssd` 热存储)
- 自动分层到 GCS 冷存储
- 销毁实例后磁盘保留

**自动扩缩容**:
- 触发条件: CPU 利用率 > 70%
- 最小实例数: 根据环境配置
- 最大实例数: 根据环境配置
- Cooldown: 5 分钟

**端口**:
- 9050: Heartbeat Service
- 9060: Thrift Service
- 8060: Brpc Service
- 8040: HTTP Web UI

### 3. Internal Load Balancer

**作用**: 为 FE 集群提供高可用访问入口

**特性**:
- 内部负载均衡 (仅 VPC 内访问)
- Health Check: TCP 9030
- 自动故障转移
- 仅在 PROD/SIT/UAT 启用

**访问方式**:
```bash
# 获取 LB IP
terraform output lb_internal_ip

# 连接
mysql -h <LB_IP> -P 9030 -u root
```

### 4. Instance Group Manager (IGM)

**作用**: 管理 BE 实例的自动扩缩容和健康检查

**功能**:
- 自动扩缩容
- 健康检查
- 自动修复
- 滚动更新

**配置**:
```hcl
enable_autoscaling = true
be_min_count = 2
be_max_count = 5
autoscaling_cpu_target = 70
```

### 5. Persistent Disks

**FE 元数据磁盘**:
- 类型: `pd-balanced` 或 `pd-ssd`
- 大小: 50GB (DEV) ~ 200GB (PROD)
- 生命周期: 保留
- 挂载点: `/opt/doris/fe/doris-meta`

**BE 存储磁盘**:
- 类型: `pd-ssd`
- 大小: 100GB (DEV) ~ 500GB (PROD)
- 生命周期: 保留
- 挂载点: `/opt/doris/be/storage`

### 6. GCS Bucket (冷存储)

**作用**: 存储冷数据，实现存算分离

**分层策略**:
- 热数据: SSD 本地存储 (高频访问)
- 冷数据: GCS 对象存储 (低频访问)
- 自动分层: 根据访问频率自动移动

**配置**:
```hcl
enable_compute_storage_separation = true
gcs_bucket_name = "doris-dev-storage"
cold_storage_retention_days = 7
```

## 网络架构

### VPC 配置

每个环境使用独立的 VPC 和网段：

- DEV: `10.0.0.0/16`
- SIT: `10.1.0.0/16`
- UAT: `10.2.0.0/16`
- PROD: `10.3.0.0/16`

### Firewall 规则

**内部通信** (VPC 内):
- 所有协议 (0-65535)
- 允许集群内部通信

**外部访问**:
- TCP 9030, 9031, 9032 (MySQL Protocol)
- TCP 8030, 8031, 8032 (HTTP)
- TCP 9010, 9011, 9012 (Edit Log)
- 可配置 IP 白名单

**SSH 访问**:
- TCP 22
- 可配置 IP 白名单

**健康检查**:
- TCP 9030
- GCP Health Check IP ranges

## 存储分层架构

### 三层存储模型

```
┌─────────────────────────────────────────────────────────┐
│                   应用层 (SQL 查询)                      │
└────────────────────────┬────────────────────────────────┘
                         │
        ┌────────────────┼────────────────┐
        │                │                │
        ▼                ▼                ▼
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  FE Memory   │  │  BE Memory   │  │   GCS Cache  │
│  (元数据缓存) │  │  (数据缓存)  │  │  (临时缓存)  │
└──────┬───────┘  └──────┬───────┘  └──────┬───────┘
       │                 │                 │
       ▼                 ▼                 ▼
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  FE Disk     │  │  BE SSD      │  │   GCS Object │
│ (持久化元数据)│  │ (热数据)     │  │  (冷数据)    │
└──────────────┘  └──────────────┘  └──────────────┘
       │                 │                 │
       └─────────────────┴─────────────────┘
                         │
                 (数据自动分层)
```

### 数据生命周期

1. **写入**: 数据先写入 BE SSD
2. **读取**: 频繁访问的数据保留在 SSD
3. **分层**: 低频访问数据自动移动到 GCS
4. **访问**: GCS 数据可透明访问（性能略低）
5. **删除**: GCS 数据根据保留策略自动清理

## 高可用架构

### FE 高可用

- 3 节点部署 (PROD)
- BDBJE 分布式元数据存储
- 自动 Leader 选举
- Load Balancer 故障转移

### BE 高可用

- Instance Group Manager 自动修复
- 健康检查自动替换异常节点
- 数据副本 (默认 3 副本)
- 持久化磁盘数据不丢失

### 存储高可用

- 持久化磁盘 (ZRS 区域级冗余)
- GCS 多区域存储
- 数据副本保护

## 扩缩容机制

### 自动扩缩容流程

```
CPU > 70%
    │
    ▼
[1] 检测到负载高峰
    │
    ▼
[2] Instance Group Manager 触发
    │
    ▼
[3] 自动创建新 BE 实例
    │
    ▼
[4] 挂载持久化磁盘
    │
    ▼
[5] 启动 BE 服务
    │
    ▼
[6] 注册到 FE 集群
    │
    ▼
[7] 开始处理查询
```

### 手动扩缩容

```bash
# 扩容
./scale.sh prod up 5

# 缩容
./scale.sh prod down 2

# 设置具体数量
./scale.sh prod set 10
```

## 数据持久化保障

### 集群销毁时的数据保护

```
terraform destroy
    │
    ├─> 删除 FE 实例
    │   └─> ✅ 保留 FE 元数据磁盘
    │
    ├─> 删除 BE 实例
    │   └─> ✅ 保留 BE 存储磁盘
    │
    ├─> 删除 Load Balancer
    │   └─> ✅ 计算资源清理
    │
    ├─> 删除 Instance Group Manager
    │   └─> ✅ 计算资源清理
    │
    └─> ✅ 保留 GCS Bucket (数据存储)
```

### 恢复集群

```bash
# 重新部署
terraform apply -var-file=terraform.tfvars.prod

# 新实例会自动挂载原有持久化磁盘
# 数据完整恢复
```

## 成本优化策略

### 1. 存储成本优化

| 存储类型 | 成本 | 适用场景 |
|---------|------|---------|
| pd-standard | $0.04/GB/月 | 不推荐 |
| pd-balanced | $0.08/GB/月 | FE 元数据 |
| pd-ssd | $0.17/GB/月 | BE 热数据 |
| GCS Standard | $0.02/GB/月 | 冷数据 |

### 2. 计算成本优化

| 实例类型 | 成本 | 优化建议 |
|---------|------|---------|
| e2-standard | 基准 | 标准配置 |
| e2-highmem | +30% | 内存密集型 |
| e2-highcpu | -20% | CPU 密集型 |
| 抢占式 | -80% | BE 节点 (可选) |

### 3. 自动扩缩容节省

- 仅在高峰期增加实例
- 低峰期自动减少实例
- 避免过度配置

## 监控指标

### 关键指标

- **FE 指标**:
  - CPU 利用率
  - 内存使用率
  - 查询延迟
  - QPS

- **BE 指标**:
  - CPU 利用率
  - 磁盘 I/O
  - 网络吞吐
  - 存储容量

- **存储指标**:
  - SSD 使用率
  - GCS 使用量
  - 数据分层比例

### 告警建议

- FE CPU > 80%
- BE CPU > 70% (触发扩容)
- 磁盘使用率 > 85%
- BE 节点离线

## 总结

本架构提供了：

✅ **多环境隔离**: DEV/SIT/UAT/PROD 完全独立
✅ **存算分离**: SSD 热存储 + GCS 冷存储
✅ **数据持久化**: 集群销毁不丢失数据
✅ **自动扩缩容**: 根据负载自动调整资源
✅ **高可用**: FE 和 BE 都支持 HA
✅ **负载均衡**: Internal LB 提供高可用访问
✅ **成本优化**: 自动扩缩容 + 存储分层
✅ **安全可靠**: 网络隔离 + 访问控制 + 数据加密

适用于生产环境的完整 Doris 部署方案。
