# 集群规划

## 概述

集群规划是 Doris 部署的第一步，合理的规划可以避免后续的很多问题。

```
┌─────────────────────────────────────────────────────────────┐
│                    集群规划要素                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │

│     ┌─────────────────────────────────────────────────┐     │
│     │  数据量 / 查询量 / 并发数 / SLA 要求            │     │
│     └─────────────────────────────────────────────────┘     │
│                                                              │
│  2. 硬件选型                                                 │
│     ┌─────────────────────────────────────────────────┐     │
│     │  CPU / 内存 / 磁盘 / 网络                       │     │
│     └─────────────────────────────────────────────────┘     │

## 一、业务需求分析

### 关键指标

| 指标 | 说明 | 影响 |
|------|------|------|
| 数据总量 | 历史数据总量 | 存储容量规划 |
| 日增量 | 每日新增数据量 | 导入性能规划 |
| 查询量 | 每日查询次数 | 计算资源规划 |
| 查询复杂度 | 查询类型和复杂度 | 内存和 CPU 规划 |
| 并发数 | 同时执行的查询数 | 并发能力规划 |
| SLA 要求 | 响应时间要求 | 性能规划 |

│                                                              │
│  存储型配置                                                  │
│  ─────────────────────────────────────────────────────────  │

│  内存:    64-128 GB                                          │
│  磁盘:    12-24 块大容量 HDD                                 │
│  网络:    10 Gbps                                            │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 硬件选型原则

| 组件 | 原则 |
|------|------|
| CPU | 多核优于高频，BE 建议每核 2-4GB 内存 |
| 内存 | FE 元数据缓存，BE 查询和导入缓存 |
| 磁盘 | SSD 优于 HDD，JBOD 优于 RAID |
| 网络 | 带宽越高越好，延迟越低越好 |

### 网络要求

| 要求 | 说明 |
|------|------|
| 带宽 | FE-BE 建议 10Gbps+，BE-BE 建议 10Gbps+ |
| 延迟 | 节点间延迟 < 1ms |
| 隔离 | 建议独立网络，避免与其他业务混用 |
| 冗余 | 网络设备双上联，避免单点故障 |

## 四、存储规划

### 存储容量估算

```
┌─────────────────────────────────────────────────────────────┐
│                    存储容量计算公式                          │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  总存储需求 = 原始数据量 × 压缩比 × 副本数 × 预留系数       │
│                                                              │
│  参数说明：                                                  │
│  ─────────────────────────────────────────────────────────  │
│  原始数据量: 业务数据原始大小                                │
│  压缩比:     Doris 压缩率，通常 3-10 倍                      │
│  副本数:     默认 3 副本                                     │
│  预留系数:   建议 1.2-1.5，预留空间                          │
│                                                              │
│  示例计算：                                                  │
│  ─────────────────────────────────────────────────────────  │
│  原始数据: 100 TB                                            │
│  压缩比: 5 倍                                                │
│  副本数: 3                                                   │
│  预留系数: 1.3                                               │
│                                                              │
│  总存储需求 = 100TB × (1/5) × 3 × 1.3 = 78 TB               │
│                                                              │
│  每 BE 存储 (假设 10 台 BE): 78TB / 10 = 7.8 TB             │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 存储类型选择

| 类型 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| NVMe SSD | 最高性能 | 成本高 | 高性能查询 |
| SATA SSD | 高性能、成本适中 | 容量较小 | 通用场景 |
| HDD | 大容量、低成本 | 性能低 | 冷数据存储 |

### 高可用设计

```sql
-- FE 高可用配置
-- Leader + Follower + Observer 模式
-- Leader 和 Follower 参与选举，Observer 不参与

-- 添加 Follower
ALTER SYSTEM ADD FOLLOWER "fe2:9010";
ALTER SYSTEM ADD FOLLOWER "fe3:9010";

-- 添加 Observer
ALTER SYSTEM ADD OBSERVER "fe4:9010";
ALTER SYSTEM ADD OBSERVER "fe5:9010";

-- 查看状态
SHOW FRONTENDS;
```

## 六、规划案例

### 案例：电商数仓集群规划

**业务需求**：
- 数据总量：50 TB
- 日增量：500 GB
- 日查询量：10 万次
- 峰值 QPS：100
- SLA：99.9%

**规划方案**：

```
集群规划方案
─────────────────────────────────────────────────────────────
1. 存储容量计算
   原始数据: 50 TB
   压缩后: 50TB / 5 = 10 TB
   3副本: 10TB × 3 = 30 TB
   预留: 30TB × 1.3 = 39 TB

2. 硬件配置
   FE (3台):
   - CPU: 16核
   - 内存: 32 GB
   - 磁盘: SSD 200 GB
   - 网络: 10 Gbps

   BE (10台):
   - CPU: 32核
   - 内存: 128 GB
   - 磁盘: 4块 2TB NVMe SSD (JBOD)
   - 网络: 25 Gbps
   - 单机存储: 8 TB
   - 总存储: 80 TB (满足 39 TB 需求)

3. 架构设计
   - FE: 3 台 (1 Leader + 2 Follower)
   - BE: 10 台
   - 副本数: 3
   - 分区策略: 按日期动态分区

4. 网络规划
   - 独立网络: 10.0.0.0/16
   - FE 网段: 10.0.1.0/24
   - BE 网段: 10.0.2.0/24
   - 客户端网段: 10.0.3.0/24

5. 预算估算
   - FE: 3 × $5,000 = $15,000
   - BE: 10 × $15,000 = $150,000
   - 网络: $10,000
   - 总计: $175,000
─────────────────────────────────────────────────────────────
```
