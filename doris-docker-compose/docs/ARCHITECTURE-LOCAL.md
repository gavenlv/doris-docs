## 核心组件

### 1. FoundationDB 集群

**部署模式**: 3 节点 Raft 集群

**资源配置**:
- 每节点: 1GB 内存
- 存储: Docker Volume (持久化)

**功能**:
- Doris 元数据存储
- 高可用保证（3 副本）
- 支持 Raft 一致性协议

**配置文件**: `configs/fdb/fdb.cluster`
```
doris_local_cluster:DorisLocal@fdb1:4500,fdb2:4500,fdb3:4500
```

### 2. Doris FE 集群

**部署模式**: 3 节点 HA 集群（1 Leader + 2 Followers）

**资源配置**:
- 每节点: 2GB 内存
- Java Heap: 512MB - 1536MB
- 存储: Docker Volume (持久化)

**端口映射**:
| 节点 | HTTP | MySQL | RPC | Edit Log |
|------|------|-------|-----|----------|
| FE1  | 8030 | 9030  | 9020 | 9010    |
| FE2  | 8031 | 9031  | 9020 | 9010    |
| FE3  | 8032 | 9032  | 9020 | 9010    |

**功能**:
- 查询解析和优化
- 元数据管理
- 查询调度
- 节点管理

**高可用机制**:
- Leader 故障自动切换
- Follower 自动接管
- 元数据强一致性

### 3. Doris BE 集群

**部署模式**: 3 节点负载均衡

**资源配置**:
- 每节点: 4GB 内存
- Storage: Docker Volume
- Cache: 20% memory

**端口映射**:
| 节点 | HTTP | Heartbeat | BRPC |
|------|------|-----------|------|
| BE1  | 8040 | 9050      | 8060 |
| BE2  | 8041 | 9051      | 8060 |
| BE3  | 8042 | 9052      | 8060 |

**功能**:
- 数据存储
- 查询执行
- 数据导入
- 副本管理

**负载均衡**:
- 查询自动路由到可用节点
- 节点故障自动剔除
- 数据自动均衡

## 高可用设计

### 1. FE 高可用

```
┌─────────────────────────────────────────┐
│          FE Leader Election             │
│                                         │
│   FE1 (Leader)                          │
│     │                                   │
│     ├─── Heartbeat ───► FE2 (Follower) │
│     │                    │              │
│     └─── Heartbeat ───► FE3 (Follower) │
│                          │              │
│   如果 FE1 故障:                         │
│   FE2 或 FE3 自动成为 Leader            │
└─────────────────────────────────────────┘
```

**故障切换流程**:
1. FE2/FE3 检测到 Leader 失联
2. 触发 Leader 选举
3. 新 Leader 接管服务
4. 客户端自动重连到新 Leader

### 2. BE 高可用

```
┌─────────────────────────────────────────┐
│        BE Load Balancing                │
│                                         │
│   FE                                    │
│    │                                    │
│    ├─ Query 1 ──► BE1 (Available)      │
│    ├─ Query 2 ──► BE2 (Available)      │
│    └─ Query 3 ──► BE3 (Available)      │
│                                         │
│   如果 BE2 故障:                         │
│   查询自动路由到 BE1 或 BE3             │
└─────────────────────────────────────────┘
```

**故障处理**:
- FE 检测 BE 节点失联
- 自动标记为 Dead
- 查询路由到其他节点
- 数据副本自动恢复

### 3. FDB 高可用

```
┌─────────────────────────────────────────┐
│        FDB Raft Consensus               │
│                                         │
│   FDB1 ◄──────► FDB2 ◄──────► FDB3    │
│    │              │              │      │
│    └────── Raft Consensus ──────┘      │
│                                         │
│   支持 1 个节点故障                      │
│   (需要 2/3 节点存活)                    │
└─────────────────────────────────────────┘
```

## 数据流转

### 1. 数据写入流程

```
┌──────────┐
│  Client  │
│ (MySQL)  │
└────┬─────┘
     │ INSERT
     ▼
┌──────────┐
│ FE Leader│
│          │
│ 1. 解析SQL
│ 2. 生成执行计划
│ 3. 分配数据分片
└────┬─────┘
     │
     ▼
┌──────────┐
│   BE1    │◄─────┐
│   BE2    │      │ 并行写入
│   BE3    │──────┘
│          │
│ 1. 接收数据
│ 2. 写入 MemTable
│ 3. Flush to Disk
└──────────┘
```

```
┌──────────┐

│ (MySQL)  │
└────┬─────┘
     │ SELECT
     ▼
┌──────────┐
│ FE Leader│
│          │
│ 1. 解析SQL
│ 2. 查询优化
│ 3. 生成执行计划
│ 4. 任务调度
└────┬─────┘
     │
     ├─────┐
     │     │
     ▼     ▼
┌──────────┐
│   BE1    │
│   BE2    │  并行扫描
│   BE3    │
│          │
│ 1. 扫描数据
│ 2. 过滤/聚合
│ 3. 返回结果

     │
     ▼
┌──────────┐

│          │
│ 1. 汇总结果

│ 3. 返回客户端
└──────────┘
```

## 性能特点

### 本地环境性能

**优势**:
- 快速启动（约 2 分钟）
- 本地网络低延迟
- 资源占用小

**限制**:
- 内存有限（21GB 总计）
- 单机部署，无分布式优势
- 性能不及生产环境

**适用场景**:
- 功能开发
- 本地测试
- SQL 调优
- 学习 Doris

## 安全配置

### 网络安全

**本地环境**:
- 仅本地访问（localhost）
- 无公网暴露
- 无加密传输

**生产环境建议**:
- VPC 隔离
- SSL/TLS 加密
- 认证授权

### 访问控制

**默认配置**:
- Root 用户无密码
- 所有节点互通

**生产环境建议**:
- 设置强密码
- 启用认证
- 配置白名单

## 扩展性

### 垂直扩展

增加单个节点资源：
```bash
# 编辑 .env
FE_MEMORY_LIMIT=3g
BE_MEMORY_LIMIT=8g

# 重启集群
docker-compose down
./scripts/start.sh
```

### 水平扩展

添加更多节点：
```bash
# 1. 编辑 docker-compose.yml，添加新节点
# 2. 启动新节点
docker-compose up -d be4

# 3. 添加到集群
mysql -h 127.0.0.1 -P 9030 -u root -e "ALTER SYSTEM ADD BACKEND 'be4:9050';"
```

## 维护操作

### 日志管理

**查看日志**:
```bash
# 所有服务
docker-compose logs -f

# 特定服务
docker-compose logs -f fe1
docker-compose logs -f be1
```

**日志位置**:
- FE: `/opt/doris/fe/log/`
- BE: `/opt/doris/be/log/`

### 数据备份

```bash
# 备份所有数据
docker-compose down
tar czf doris-backup-$(date +%Y%m%d).tar.gz \
    /var/lib/docker/volumes/doris-local_*

# 恢复数据
docker-compose down
tar xzf doris-backup-*.tar.gz -C /
docker-compose up -d
```

## 故障恢复

### 单节点故障

**FE 故障**:
```bash
# 重启故障节点
docker-compose restart fe1

# 如果无法恢复，删除并重建
docker-compose stop fe1
docker volume rm doris-local_fe1-data
docker-compose up -d fe1
```

**BE 故障**:
```bash
# 从集群移除
mysql -h 127.0.0.1 -P 9030 -u root -e "ALTER SYSTEM DROP BACKEND 'be1:9050';"

# 重启节点
docker-compose restart be1

# 重新添加
mysql -h 127.0.0.1 -P 9030 -u root -e "ALTER SYSTEM ADD BACKEND 'be1:9050';"
```

### 集群故障

```bash
# 完全重置
./scripts/reset-cluster.sh
```

## 最佳实践

### 1. 资源规划

- **最小配置**: 16GB 内存 + 50GB 磁盘
- **推荐配置**: 32GB 内存 + 100GB 磁盘

### 2. 数据管理

- 定期清理测试数据
- 监控磁盘使用
- 适时删除不需要的表

### 3. 性能优化

- 收集统计信息
- 合理设计分区分桶
- 避免大事务

### 4. 安全建议

- 不要在生产环境使用本地配置
- 设置访问密码
- 限制网络访问

## 总结

本地 Docker Compose 环境提供了一个快速、便捷的 Doris 集群，适合：

- ✅ 本地开发
- ✅ 功能测试
- ✅ SQL 学习
- ✅ 性能调优

但不适合：

- ❌ 生产环境
- ❌ 高并发场景
- ❌ 大数据量测试

对于生产环境，请使用 GKE 部署方案。
