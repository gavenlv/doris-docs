## 2.2 核心概念

### Tablet（数据分片）

**为什么需要 Tablet？**

- 数据按分桶分散存储
- 每个 Tablet 有多个副本保证高可用
- 查询时只扫描需要的 Tablet

### 数据模型

| 模型 | 适用场景 | 特点 |
|------|----------|------|
| DUPLICATE | 日志、事件流 | 保留所有原始数据 |
| AGGREGATE | 报表、统计 | 自动聚合，节省存储 |
| UNIQUE | 维度表、主键 | 保证唯一性 |

### 分区（Partition）

**为什么需要分区？**

- 按时间分区，方便数据管理
- 查询时可做分区裁剪，减少扫描量
- 支持分区级别的数据过期管理

## 2.3 查询执行流程

```
1. 客户端提交 SQL
         │
         ▼
2. FE 接收并解析 SQL
         │
         ▼
3. 语义分析和重写
         │
         ▼
4. 查询优化 (CBO)
         │
         ▼
5. 生成执行计划
         │
         ├──────────────────┐
         ▼                  ▼
6. 任务下发 BE        7. BE 本地执行
         │                  │
         └────────┬─────────┘
                  ▼
            8. 结果汇总到 FE
                  │
                  ▼
            9. 返回结果给客户端
```

## 2.4 高可用机制

### FE 高可用

- 3 节点 FE 集群
- Leader 通过 BDBJE 选举产生
- Follower 自动同步元数据

### BE 高可用

- 每个 Tablet 3 副本存储
- Primary 写入后同步到 Replica
- BE 故障时自动剔除并恢复
